# Contributing to AirEye

Thank you for your interest in contributing. AirEye is a mobile-first document
image workflow application — contributions must align with this purpose.

## Alignment Requirements

All contributions must support legitimate document image workflow use cases.
Features related to the following will be rejected:

- Surveillance or hidden capture
- Unauthorized data collection
- Credential theft or permission bypassing
- Anti-detection behavior

## Getting Started

1. Fork the repository
2. Create a feature branch from `main`
3. Make your changes following the code style guides in `docs/code-rules/`
4. Write or update tests for your changes
5. Ensure all tests pass
6. Submit a pull request using the PR template

## Code Style

This project maintains style and architecture guides in `docs/code-rules/`:

- `project-architecture.md` — overall architecture conventions
- `code-practice.md` — general coding standards
- `restriction.md` — constraints and boundaries
- `unit-test-rules.md` — testing standards
- `mobile-code-rules.md` — Flutter/mobile conventions

## Pull Request Process

1. Use the pull request template provided
2. Describe what your change does and why
3. Note any security or privacy implications
4. Ensure CI passes before requesting review

## Security Concerns

If you discover a security issue, do not open a public issue. See
[SECURITY.md](SECURITY.md) for the disclosure process.
